#### US-08 — Подсказки о недостающих данных (★, Must, MVP)

## Часть 5. Основные User Flows

Нотация шагов: `узел` — Screen ID из реестра; `(T-xxx)` — ребро из `transitions.json`; ✅ 🟡 ⚪ 🔵 🟣 🔴 — статус реализации по соглашению [01-screen-inventory.md](01-screen-inventory.md). **Развилка** — точка выбора пользователя или системы.

### F-01 Регистрация, активация, вступление

- **Роль:** ANON → USER → MEMBER · **US:** US-01, US-02 · **BR:** BR-001…003
- **Старт (три входа):**
  - (a) *Самостоятельная регистрация:* `S-AUTH-01`(signUp) ✅ → `S-REQ-01` (T-003) → пользователь без организации → `S-SYS-01` (T-016) → `M-SYS-01` (T-017) или ожидание.
  - (b) *Активация аккаунта:* письмо `EXT-01` → `S-AUTH-02` ✅ (T-008) → «Активировать и войти» → `S-REQ-01` (T-009).
  - (c) *Вступление по ссылке:* `M-SYS-03` → `S-AUTH-03` ✅ (T-011): гость — регистрация и заявка за один шаг, залогиненный — только заявка → `S-SYS-01` (pending) (T-014) → решение владельца (`M-PRT-03` / `M-PRT-04`) → `S-SYS-01` опрашивает каждые 30 с → `S-REQ-01` (T-019) или «Заявку отклонили» + причина.
- **Развилки:** у гостя нет аккаунта / есть; ссылка работает / не работает; уже участник («Вы уже в …»); есть pending-заявка.
- **Ошибки:** `S-AUTH-02` loadError → «Войти» (T-010); `S-AUTH-03` loadError → «На главную» (T-015); валидация формы.
- **Пробелы:** `S-AUTH-04` сброс пароля 🟣; регистрация без подтверждения email; `/activate` и `/join` без гварда (перезапись чужой сессии); приглашение существующему пользователю принимается из `M-SYS-05` (T-038) — это скрытый вход (d).

### F-02 Создание организации и сбор команды (владелец)

### F-03 Создание и публикация формы

### F-04 Публичная подача заявки (заявитель)

- **Роль:** ANON · **US:** US-05, US-06, US-08, US-24 · **BR:** BR-012, BR-013, BR-015, BR-020, BR-028
- **Шаги:** `S-PUB-01` (T-043 из легаси) → ввод описания ≥10 символов → `ST-PUB-01-suggesting` (T-050) → `S-PUB-01.1` (T-051) → «Выбрать» → `S-PUB-02` (T-053) → страницы формы + «Ваши контакты» → «Отправить заявку» → `S-PUB-01.2` (T-056).

### F-05 Внутренняя подача заявки (участник)

### F-06 Telegram: привязка и создание заявки

- **Роль:** MEMBER/OWNER (сотрудник) · **US:** US-07, US-27 · **BR:** BR-060…062

### F-08 Взять заявку в работу

- **Роль:** MEMBER/OWNER · **US:** US-09, US-10, US-11, US-27, US-30 · **BR:** BR-022, BR-025
- **Старт:** уведомление `M-SYS-05` (T-035) / `TG-07` (T-040) либо вход в `S-REQ-01` (таб «Свободные» по умолчанию).
- **Шаги:** «Взять» в `S-REQ-01` (T-102) / `S-REQ-03` (T-122) / `TG-06` (T-611) / `TG-07` (T-610) → `new → planning`, ответственный = взявший → `S-REQ-03.2`.
- **Альтернативы:**
  - владелец назначает ответственного: `M-REQ-06` (T-124, T-125);
  - «Сделаю сам»: `M-REQ-04` (T-126, T-127) → сразу `in_progress`;
  - «Отказаться»: `M-REQ-05` (T-128, T-129) → `planning → new`, заявка снова в «Свободные».
- **Развилки:** взять самому / ждать назначения владельцем; найти заявку в табе / открыть из уведомления.
- **Ошибки:** конкурентное взятие (в backend первый побеждает, сообщение второму в UI не подтверждено).
- **Пробелы:** уведомление о новой заявке получают только владельцы (GAP-19); в реестре нет поиска и фильтров (GAP-33); применение AI-плана из `new` лишает заявку ответственного и уводит из «Свободных» (GAP-17).

### F-09 Планирование и исполнение (куратор)

- **Роль:** RESP/OWNER, ASSIGNEE · **US:** US-12, US-14, US-15, US-18, US-21, US-28, US-29 · **BR:** BR-021, BR-030…037, BR-073…074
- **Шаги:**
  1. `S-REQ-03` → вкладка «Этапы» `S-REQ-03.2` (T-111).
  2. План: AI — «Предложить план» → `M-REQ-10` (T-137, T-138, 🔴) либо вручную `M-REQ-07` (T-130, T-131).
  3. Исполнитель: `M-REQ-09` (T-134, T-135) — рекомендации, участники, подрядчики.
  4. «Запустить» `planning → in_progress` (T-123).
  5. Этап завершает исполнитель `M-REQ-08` (T-132, T-133) либо `TG-08` (T-608, T-609); при последнем этапе заявка автоматически `completed`.
  6. «Закрыть заявку» `M-REQ-01` (T-116, T-117) → `closed`.
  7. «В архив» `M-REQ-03` (T-120, T-121) → `archived`.
- **Альтернативы:** «Отменить» `M-REQ-02` (T-118, T-119); добавить этап в завершённую заявку → `planning` (T-131); «Снять блокировку» (T-136).
- **Развилки:** AI-план vs ручные этапы; сотрудник vs подрядчик; закрыть vs вернуть в планирование.
- **Ошибки:** AI-задача failed / polling до 5 минут; нельзя запустить без ответственного и исполнителя первого этапа; нельзя завершить без результата.
- **Пробелы:** заблокировать этап `M-REQ-14` 🟣 (GAP-16); ТЗ этапа `M-REQ-15` 🔵 (GAP-15); вкладка «История» `S-REQ-03.5` ⚪ (US-14, GAP-14); входные материалы нельзя загрузить в UI (GAP-16).
