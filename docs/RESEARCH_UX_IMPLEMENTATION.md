# Реализация UX-концепции исследований

Обновление от 11 ноября 2026 года: главная и оболочка самостоятельного сервиса заменены согласно [ТЗ главной](HOME_PAGE_REFACTOR_SPEC.md). Актуальная навигация: главная `/surveys`, исследования `/surveys/studies`, проекты `/surveys/projects`; выбор команды и профиль находятся в сайдбаре. Описание главной и дерева ниже отражает предыдущую итерацию. Конструктор, публикация и результаты продолжают использовать описанные здесь сценарии.

Основание: «ТЗ_UX_концепция_платформы_исследований.md», версия 1.0 от 10 ноября 2026 года. Реализация развивает существующий React / Ant Design интерфейс и API опросов. Документ описывает передачу изменений в разработку и ограничения проверки; он не означает прохождения пользовательской UX-валидации.

## Что изменилось относительно текущего интерфейса

- Главная начинается с поля для исследовательской задачи и объяснения, как ИИ поможет подготовить опрос. Проекты и недавние исследования расположены ниже; ручное создание доступно рядом с полем.
- В самостоятельном сервисе команда выбирается в шапке. Меню содержит доступные пространства, участников команды, настройки и тариф для владельца.
- Дерево проектов появляется внутри проекта и исследования. На компьютере его можно свернуть; на узком экране используется существующая выдвижная навигация. Настройки, тариф и участники доступны из меню пространства в шапке.
- Центральный чат используется при подготовке нового исследования. Рабочая область сохранённого исследования показывает конструктор, публикацию и результаты. Аналитический ИИ открывается отдельно справа или в drawer на телефоне.
- В конструкторе предложения ИИ больше не применяются автоматически: виден будущий набор вопросов, есть применение, отклонение и отмена. После ручного изменения основы устаревшее предложение нельзя применить, а отмена не перезаписывает последующие ручные правки.
- Публикация выделена в страницу с предпросмотром, фактическим статусом, ссылкой и подтверждением остановки приёма.
- Результаты разделены на обзор, вопросы, ответы и ИИ-инсайты. Источники инсайта ведут к соответствующим агрегатам вопросов.

## Сущности и навигация

Сохраняется реальная модель `Organization → SurveyProject → Survey`. В интерфейсе Survey используется как первая методика исследования, опрос. Новые методики, произвольные вложенные папки и новые доменные статусы не добавлены.

- `/surveys` — главная с проектами и недавними исследованиями.
- `/surveys/projects/:projectId` — существующая страница проекта.
- `/surveys/create[?project=:projectId]` — подготовка опроса с ИИ.
- `/surveys/create?mode=manual[&project=:projectId]` — ручной конструктор.
- `/surveys/:id` — структура сохранённого опроса, предпросмотр и вход в редактирование.
- `/surveys/:id/edit` — полноценный конструктор, статус и переходы к публикации и результатам.
- `/surveys/:id/publication` — публикация и управление приёмом ответов.
- `/surveys/:id/results/overview` — сводные показатели.
- `/surveys/:id/results/questions` — распределения и аналитика вопросов.
- `/surveys/:id/results/responses[/:responseId]` — первичные ответы.
- `/surveys/:id/results/insights` — выводы ИИ с основаниями.

Старые адреса `/form`, `/analytics`, `/responses[/:responseId]` продолжают работать. Публичные ссылки `/survey/:token` и маршрут предпросмотра не изменены. Маппинг разделов и распознавание неизвестных адресов вынесены в `src/shared/utils/researchNavigation.ts`.

## Основные сценарии

1. Главная → описание задачи → создание опроса → чат и черновик → выбор проекта (или серверный проект по умолчанию) → «Открыть черновик в конструкторе» → проверка и сохранение.
2. Главная → «Создать опрос вручную» → ручное редактирование → сохранение. ИИ для этого пути не требуется.
3. Проект → создание → тот же сценарий с заранее выбранным проектом.
4. Конструктор → запрос ИИ → проверка предложенного набора → применение или отклонение → при необходимости отмена → сохранение.
5. Исследование → публикация → предпросмотр → публикация → копирование ссылки → при необходимости подтверждённая остановка сбора.
6. Исследование → результаты → ИИ-инсайты → ссылка на вопрос → распределение / первичные данные.
7. Смена команды → проверка несохранённой работы → сброс контекста → главная выбранной команды.

## Состояния и сохранение

- Загрузка и ошибка проектов используют существующие skeleton и повторную загрузку. Ошибка списка недавних исследований показана отдельно от пустого состояния.
- При отсутствии вопросов публикация недоступна. При неудачной публикации статус сохраняется, действие можно повторить.
- При нулевом числе ответов аналитика показывает пустое состояние. Ошибка загрузки агрегатов не блокирует конструктор и публикацию.
- Наблюдателю не предлагаются создание, редактирование, публикация и генерация ИИ. Уже сформированные инсайты доступны для чтения. Серверная авторизация остаётся обязательной.
- Содержимое исследования проверяется на соответствие активному пространству; смена пространства пересоздаёт контекст страниц.
- Перед уходом из изменённого конструктора, сменой команды и закрытием вкладки показывается предупреждение. Статус сохранения явно различает новый черновик, изменения, сохранение и ошибку.
- Подготовка с ИИ и её история сохраняются в `sessionStorage` с ключом пользователя, пространства и проекта/исследования. Черновик восстанавливается при обновлении этой вкладки; после создания передаётся в редактор. Закрытие правой панели не очищает переписку и предложения.
- Это не серверное автосохранение и не синхронизация истории между устройствами. При недоступном browser storage остаются работа в памяти и предупреждение перед уходом.
- ИИ-инсайты показывают размер использованного набора, ограничения интерпретации, устаревание и несовпадение фильтра качества. Ссылки на основания не обозначают причинную связь.

## Реальные ограничения backend

Используются существующие статусы `draft`, `open`, `closed`, `archived`; состояние «готов к публикации» не имитируется отдельным серверным статусом. Правки структуры при наличии ответов по-прежнему проверяет сервер (`survey_structure_locked`). Ответы уже содержат snapshot схемы; новая система неизменяемых публикаций/версий в эту UI-работу не включена.

Просмотры и незавершённые прохождения не добавляются к метрикам: используем только реально доступные агрегаты. ИИ возвращает источники на уровне вопросов; индивидуальные ответы доступны через существующую аналитику и список ответов. Публикация показывает существующие настройки анонимности и закрытия, не обещает новые способы рекрутинга или ограничения доступа.

## Проверки

```powershell
npm run build:surveys
npm run build
npx eslint src scripts/test-research-navigation.ts
npm run test:logic
npm run test:research
npm run test:research:ui
```

Для браузерного теста нужен доступный Playwright и Chromium. При внешней установке задайте `PLAYWRIGHT_MODULE_PATH` (путь к модулю), при необходимости `CHROME_EXECUTABLE` (путь к браузеру). `RESEARCH_SCREENSHOT_DIR` задаёт каталог снимков. Тест сам запускает preview собранной `dist-surveys` на `127.0.0.1:5177`; `RESEARCH_TEST_URL` позволяет выбрать уже запущенный сервер. Все API-запросы изолированы тестовыми ответами, реальные аккаунты и данные не используются.

Полный `npm run lint` также сканирует документационные JS-файлы и обнаруживает существующий `return` вне функции в `docs/c4/build-figjam.js:138`. Эта генерация FigJam не относится к изменённому интерфейсу. Vite предупреждает о существующих крупных chunks библиотек и географических данных.

## Что требует отдельной проверки

Приложение является работающим прототипом P0 для сценарной проверки. Интервью и UX-тесты с 5–8 участниками, проверка гипотез карточек/дерева, согласование продуктовых решений, отдельный комплект Figma wireframes/high-fidelity макетов и финальная приёмка владельцем продукта не проводились. Их нельзя заменять автоматическими тестами или объявлять завершёнными по результатам сборки.

Для UX-сессий использовать контрольные сценарии исходного ТЗ: глобальное создание, ручной старт, правка ИИ-вопроса, переключение исследования через дерево, смена команды, публикация и проверка основания инсайта. Дополнительно проверить клавиатуру, узкий экран, долгую генерацию, сетевую ошибку и восстановление подготовленного черновика.
