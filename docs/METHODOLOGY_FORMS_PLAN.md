# План: генерация форм на основе целей и методик исследований

Источник: Google Doc «для создания форм» (5 направлений: маркетинговые исследования, академические опросы, CustDev, CX-метрики, UX-исследования).
Дата: 2026-10-20

---

## 1. Суть новой функциональности

1. Пользователь пишет промпт («нужна анкета для курсовой по лояльности студентов к вузу»).
2. СВОД **определяет цели и подбирает методики** из каталога.
3. По выбранным методикам **генерируется форма** (с правилами методик, а не «просто вопросы»).
4. Доработка — дополнительными промптами или вручную в конструкторе (уже есть).
5. После создания — **краткая сводка**: какие методики использованы и где.
6. По кнопке — **полный обзор методик и методологий** (авторы, книги, стандарты) в виде текста для вставки в раздел «Методология исследования» письменной работы.

## 2.1 Решение по продукту: отдельный модуль «Опросы»

Функциональность выносится в **отдельный раздел «Опросы»**, не смешиваясь с «Формами» (формы заявок остаются как есть).

| | Формы (сейчас) | Опросы (новое) |
|---|---|---|
| Для чего | принять заявку внутри организации | собрать ответы респондентов (исследование) |
| Результат отправки | создаётся заявка, workflow, исполнители | сохраняется ответ респондента (response), заявок нет |
| Респондент | клиент/коллега организации | аноним или по ссылке, «подопытный» |
| ИИ | подбор полей по описанию | подбор целей и методик + сводка + обзор для работы |
| Публичная страница | `/form/:token/fill/:formId`, шапка организации | `/survey/:token` — чистая страница опроса, без заявочной терминологии |

**Меню:** `Заявки · Формы · Опросы · Участники · Настройки` (`navItems.ts`, маршруты `/surveys`, `/surveys/create`, `/surveys/:id`, `/surveys/:id/edit`, `/surveys/:id/responses`).

**Что переиспользуем:** конструктор (`FormEditor`, поля, рендер), AI-панель, `openrouter_client`, файловые поля, санитайзер.
**Что делаем новым:** сущности `Survey` и `SurveyResponse` (отдельные таблицы, не `requests`), публичный токен опроса, страница респондента, раздел результатов.

### Экраны
1. **Список опросов** — название, направление (чип), использованные методики, число ответов, статус (черновик / открыт / закрыт), ссылка.
2. **Создание** — слева промпт и доработки чатом, справа конструктор; над ним карточка «Использованные методики» (чипы, цель, предупреждения), кнопки «Подробный обзор методик» и «Изменить набор».
3. **Обзор методологии** — модалка/drawer: связный текст для раздела работы, «Копировать», «Скачать .docx», список литературы по ГОСТ.
4. **Страница респондента** — одна форма на экран или по страницам, прогресс-бар, мобильная вёрстка, экран благодарности. Без полей и слов из «заявок».
5. **Результаты** — число ответов, сводка по вопросам, метрики (NPS/CSAT/CES/SUS), отсев по attention check, экспорт CSV. (Минимум на MVP — счётчик и экспорт CSV.)

### Модель данных (дополняет §5.2)
- `surveys`: id, organization_id, created_by_user_id, name, description, pages (JSONB), `methodology_meta` (JSONB), status (`draft|open|closed`), public_token, anonymous (bool), closes_at, created_at, updated_at.
- `survey_responses`: id, survey_id, answers (JSONB), `schema_snapshot` (снимок схемы на момент ответа), `quality_flags` (JSONB: провален attention check, слишком быстрое заполнение), submitted_at, respondent_meta (UA, без персональных данных при `anonymous`).
- Миграция `028` создаёт обе таблицы (вместо колонки `forms.methodology_meta`).
- API: `/surveys` CRUD, `POST /surveys/ai-builder`, `GET /surveys/{id}/methodology-report`, `GET /surveys/{id}/responses`, `GET /surveys/{id}/responses/export.csv`; публичные: `GET /public/surveys/{token}`, `POST /public/surveys/{token}/responses` (с rate limit как у `public_suggest_rate_limit`).

## 3. Пробелы между документом и текущими возможностями

**Типы полей, которых не хватает:**

| Нужно для | Новый тип / доработка |
|---|---|
| Шкала Лайкерта, SUS, UEQ | `matrix` / `likertGrid` — таблица утверждений × шкала (5/7 баллов, подписи полюсов) |
| Семантический дифференциал (Осгуд) | `semanticDifferential` — биполярные пары, шкала 5–7 |
| Conjoint Analysis | `choiceTask` — набор карточек-сценариев (комбинации атрибутов), выбор одной |
| Сценарное тестирование (UX) | `task` — инструкция + поля «время / где запутались»; на старте можно собрать из `longText` + `number` |
| Attention checks | флаг `attentionCheck: { correct: ... }` в `config` у `radio`/`dropdown`; в публичной форме выглядит как обычный вопрос |
| NPS | есть (`rating`, variant `nps`) — добавить связку «NPS + обязательный открытый вопрос» |
| CES, CSAT | покрываются `rating` (numeric_scale) с фиксированными формулировками |

**Контент, которого нет вообще:** каталог методик, правила генерации, справочник источников.

## 4. Замечания к исходному документу (проверить до внедрения)

Это пользовательский контент, который попадёт в работы студентов — ошибки в источниках недопустимы.

- **Lean Canvas** принадлежит Эшу Маурье (Ash Maurya), а не Остервальдеру (он автор Business Model Canvas).
- **ГОСТ Р ИСО 20252** — проверить актуальную редакцию и год (в документе указан 2012) и точное название.
- **ГОСТ Р 59128-2020** — проверить номер, название и статус.
- Русские названия книг (Райхельд, Диксон, Бланк, Кристенсен, Круг) — сверить с реальными изданиями: издательство, год, ISBN, переводчик — нужны для библиографического списка.
- «10 эвристик Нильсена» — это статья/набор принципов, а не книга; оформлять как электронный ресурс.
- SUS и UEQ — стандартные опросники со своими условиями использования (атрибуция, лицензия на тексты вопросов); формулировки брать из официальных русскоязычных валидированных версий, а не «по памяти ИИ». Формулировки SUS/UEQ/NPS **фиксируются в шаблонах, LLM их не переписывает**.
- «ИИ должен знать SUS наизусть» → реализуем детерминированным шаблоном, а не промптом.
- Формулировка «ГОСТ даёт доверие научруков» — в интерфейсе писать аккуратно («составлена с учётом принципов…»), без утверждения о сертификации.

## 5. Архитектура решения

```
промпт ──► [Этап 1: Intent] ──► {goals[], methodologies[], audience, language}
               │ (LLM, structured JSON, видит только каталог: id + when-to-use)
               ▼
        [Этап 2: Генерация] ◄── правила и шаблоны выбранных методик
               │ (LLM; в промпт подмешиваются rules выбранных методик;
               │  фиксированные блоки — NPS/SUS/CES/attention — вставляются кодом)
               ▼
        [Этап 3: Валидаторы] ── Mom Test lint, double-barreled, leading, жаргон,
               │                 длина анкеты, наличие attention check
               ▼        (при нарушениях — одна автоправка LLM, затем предупреждения)
        санитайзер (уже есть) ──► pages + methodology_summary
               ▼
        сохранение: forms.methodology_meta (JSONB)
               ▼
        GET /forms/{id}/methodology-report  (полный обзор, кэш)
```

### 5.1 Каталог методик (данные, не код)

Каталог хранится в репозитории: `backend/app/knowledge/methodologies/*.yaml` (по файлу на направление) + `sources.yaml`.

Запись методики:
```yaml
id: nps
category: cx_metrics            # 1 из 5 направлений
name: Net Promoter Score (NPS)
goal: Измерить лояльность клиентов
when_to_use: ...                # используется на этапе 1
generation_rules: ...           # фрагмент промпта для этапа 2
template: {...}                 # готовый блок полей (если методика стандартизирована)
validators: [nps_has_open_followup]
required_field_types: [rating]
sources: [reichheld_ultimate_question]
summary_ru: ...                 # 1–2 предложения для краткой сводки
detailed_ru: ...                # текст для полного обзора (описание, как применялось, ограничения)
```
Источники (`sources.yaml`): авторы, название, издание, год, ISBN/URL, готовая библиографическая запись по ГОСТ Р 7.0.100.

**Содержание каталога (из документа):**

| # | Направление | Методики |
|---|---|---|
| 1 | Маркетинговые исследования | Conjoint, психографическая сегментация (VALS), «5 почему» |
| 2 | Социологические/академические | Лайкерт, семантический дифференциал, когнитивное интервьюирование (как набор правил-линтеров), attention checks |
| 3 | CustDev | The Mom Test, JTBD, Lean Canvas (блоки канвы как цели вопросов) |
| 4 | CX | NPS, CSAT, CES |
| 5 | UX | SUS, UEQ, сценарное тестирование |

### 5.2 Модель данных

- Миграция `028_form_methodology_meta`: `forms.methodology_meta JSONB NULL`.
- Структура: `{ catalog_version, goals[], methodologies[{id, applied_to_field_ids[]}], generated_at, prompt_excerpt, standards_note }`.
- Метаданные обновляются при последующих ИИ-доработках (пересчёт набора методик); ручные правки поля не ломают — `applied_to_field_ids` просто теряют удалённые id.
- `FormResponse` и `Create/UpdateFormRequest` расширяются полем `methodology_meta`.

### 5.3 API

| Метод | Назначение |
|---|---|
| `POST /forms/ai-builder` (расширить) | ответ + `methodology_summary` (список методик, цели, предупреждения валидаторов). Обратная совместимость: поле необязательное |
| `GET /forms/{id}/methodology-report?format=json\|md\|docx` | полный обзор: описание каждой методики, обоснование выбора для данной формы, источники, стандарты, библиография |
| `GET /methodologies` | каталог для ручного выбора/редактирования набора методик |

### 5.4 Frontend

- `AiFormBuilderPanel`: после генерации — карточка «Использованные методики» (чипы + 1 строка на методику, цели, предупреждения линтера). Кнопка «Подробный обзор».
- Модалка/Drawer «Обзор методологии»: структурированный текст, «Скопировать», «Скачать .docx/.md», блок «Список литературы».
- Возможность вручную добавить/убрать методику (чипы из `/methodologies`) и перегенерировать.
- Новые компоненты полей в конструкторе, превью и публичной форме: `matrix`, `semanticDifferential`, `choiceTask` (+ регистрация в `fieldRegistry`/Formily-схеме, если используется).
- Просмотр сохранённой формы (`FormViewPage`): та же сводка + ссылка на обзор.

## 6. Этапы реализации

### Этап 0 — Контент и решения (блокирует остальное)
- Утвердить 5 направлений и список методик (§5.1).
- Проверить источники и ГОСТы (§4), собрать `sources.yaml`.
- Получить официальные формулировки SUS, UEQ, NPS/CSAT/CES (RU).
- Решить открытые вопросы (§8).

### Этап 1 — Каталог и подбор методик (backend)
- Загрузчик каталога + pydantic-схемы + тесты на валидность YAML.
- Этап 1 пайплайна: intent-классификатор → `{goals, methodologies}` (structured JSON, ограничение выбора только id из каталога, 1–3 методики).
- Расширение промпта генерации правилами выбранных методик.
- Расширение `FormAiBuildResponse` (`methodology_summary`).

### Этап 2 — Детерминированные шаблоны и новые типы полей
- Backend: типы `matrix`, `semanticDifferential`, `choiceTask` в `FIELD_TYPE_DESCRIPTIONS` и санитайзере; поддержка `attentionCheck` в config.
- Шаблоны NPS (+открытый вопрос), CSAT, CES, SUS, UEQ вставляются кодом, не LLM.
- Frontend: компоненты полей для конструктора, превью, публичной формы, сохранение/чтение в `forms.api.ts`.
- Генератор conjoint-сценариев (ортогональный/частичный фактородизайн — на MVP ограниченный набор карточек из 2–4 атрибутов).

### Этап 3 — Валидаторы качества вопросов
- Правила (regex + LLM-критик одним вызовом):
  - Mom Test: запрет «вы бы купили/стали бы», гипотетика и будущее → переформулировка в прошлый опыт.
  - Double-barreled («и» в вопросе о двух сущностях), наводящие вопросы, жаргон, двусмысленность.
  - Академические анкеты: наличие attention check, длина (порог вопросов), единая шкала.
- Одна автоправка + показ оставшихся предупреждений в сводке.

### Этап 4 — Метаданные и отчёт
- Миграция `028`, обновление моделей/схем/сервиса форм.
- Сервис отчёта: сборка из каталога + LLM-абзац «обоснование выбора» под конкретную форму; кэш в `methodology_meta`.
- Экспорт md/docx.

### Этап 5 — UI сводки и обзора
- Карточка сводки, модалка обзора, копирование/скачивание, ручной выбор методик, отображение на `FormViewPage`.

### Этап 6 — Качество и выпуск
- Тесты backend (по образцу `backend/tests/test_request_draft_ai.py`: мок `post_chat_completion`): подбор методик, санитайзер новых типов, валидаторы, шаблоны, отчёт.
- Eval-набор: ~25 эталонных промптов (по 5 на направление) с проверкой — выбрана ли ожидаемая методика, нет ли запрещённых формулировок; прогон перед сменой модели/каталога.
- Frontend: lint/build, ручная проверка сценариев в браузере.
- Обновить `docs/` (PROJECT_OVERVIEW, API_RULES) и `README`.

## 8. Открытые вопросы к владельцу продукта

1. Язык обзора и библиографии: только русский, формат ГОСТ Р 7.0.100 — подтвердить.
2. Нужен ли экспорт обзора в .docx на MVP или достаточно «скопировать текст»?
3. Привязана ли функция к тарифу/организации (стоимость LLM-вызовов: теперь 2–3 на генерацию)?
4. Нужны ли результаты (подсчёт NPS/CSAT/CES/SUS, отсев по attention check) в разделе ответов — это отдельный объём работ.
5. Conjoint: достаточно «показать карточки и сохранить выбор» или нужен расчёт частных полезностей?
6. Показывать ли респонденту отметку «составлено с учётом ГОСТ Р ИСО 20252» — юридически/репутационно проверить формулировку.

## 9. Риски

- **Галлюцинации в источниках** → источники только из проверенного `sources.yaml`, LLM их не генерирует.
- **Рост латентности/стоимости** (2 LLM-вызова + критик) → маленькая модель для этапа 1, таймауты, кэш обзора.
- **Лицензии опросников** (SUS/UEQ) → проверить условия, указывать атрибуцию.
- **Несовместимость старых форм** → `methodology_meta` необязательное, новые типы полей с fallback-рендером в старых клиентах.

**Дашборд анализа результатов (2026-10-22, по документу «для анализа результатов»)**
- Страница опроса: сводная панель (даты сбора, кнопки «Поделиться ссылкой», «Экспортировать данные (CSV)», «Сгенерировать AI-отчёт», «Спросить ИИ», фильтр качества) и вкладки «Обзор», «Количественный анализ», «Ответы». Список опросов: колонка «Последний ответ» (`last_response_at`) и кнопка «Анализировать».
- Обзор: счётчики (всего, полнота ответов, среднее и медианное время), круговые диаграммы сегментов, метрики NPS/CSAT/CES/SUS/UEQ, AI-резюме (3–5 выводов; кэшируется в `surveys.ai_summary`, миграция `029`; в данные для модели входят сравнения по сегментам).
- Количественный анализ: описательная статистика (среднее, медиана, мода, σ), диаграммы по вопросам (`@ant-design/charts`), кросстабуляция `GET /surveys/{id}/crosstab` (таблица с χ², p, V Крамера или средние по группам; расчёт на stdlib в `stats_math.py`, без numpy/scipy).
- AI-чат по результатам (`POST /surveys/{id}/ai-chat`, `survey_ai_analysis_service`): модель планирует срез, сервер считает кросстаб и собирает открытые ответы группы, цитаты возвращаются по id и подставляются сервером (выдумать цитату нельзя); ответы респондентов подаются как данные, не инструкции.
- «Полнота ответов» — средняя доля отвеченных вопросов: честный процент завершения невозможен, пока не сохраняются начатые, но не отправленные анкеты.
